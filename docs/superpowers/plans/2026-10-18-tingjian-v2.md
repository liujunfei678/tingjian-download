# Tingjian 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Deliver the approved persistent audio workbench with name groups, arbitrary download folders and the existing M4A converter.

**Architecture:** MV3 global side panel, service-worker task coordinator, framed native messaging Windows host reusing ConverterCore.cs. Browser downloads preserve browser credentials; app-owned staging files are published by the host without overwrites.

**Tech Stack:** Existing vanilla JS/CSS, Chrome APIs, C# 5/.NET Framework, FFmpeg, Node test runner and Playwright.

**Spec:** ../specs/2026-10-18-tingjian-workbench-design.md (approved by user 2026-10-18).

## Global Constraints
- Version 2.0.0, Windows 10/11 Chrome/Edge; no account or upload.
- Two name groups use nameRecognized, never verified.
- Existing naming and capture protections and standalone converter stay supported.
- Native setup is per-user, explicit installer execution; no registry changes during development.
- Unique staging task directories; publish atomically, never overwrite, clean only owned files after recording success.
- Keep files uncommitted: repository has no HEAD or configured identity. Create codex/tingjian-v2 unborn branch and keep baseline backup.

## Review Focus
- Late responses after tab/window changes must not replace current resources (Task 2).
- Hash filenames and page-title fallbacks must stay unrecognized (Task 1).
- Interrupted/closed panels must not drop running tasks or mark failures successful (Task 3).
- Untrusted webpage messages and path traversal must not invoke native file operations (Task 3).
- Chinese filenames, collisions and failed publishing must preserve original/staging files (Task 3).

## Shared interfaces
UI requests use chrome.runtime.sendMessage and existing {ok,data,error} envelope. Existing GET_AUDIO/SCAN_TAB/CLEAR_TAB/DOWNLOAD_AUDIO retained. DOWNLOAD_AUDIO accepts convert:true for M4A.
GET_WORKBENCH, NATIVE_CONNECT, SAVE_SETTINGS {settings}, CHOOSE_DIRECTORY {purpose:'download'|'conversion'}, ADD_CONVERSION_FILES {folder,recursive}, START_CONVERSION {ids?}, CANCEL_CONVERSION, RETRY_CONVERSION {id}, RETRY_DOWNLOAD {id}, OPEN_TASK {id,reveal}, CLOSE_PANEL {windowId}.
Workbench snapshot and storage.local.workbench: {prefs:{downloadMode:'browser'|'custom',downloadDirectory,conversionDirectory,bitrate:320,saveAs:false,recursive:false},host:{connected,version,error},downloads:[],conversions:[]}. Task fields id,name,state,progress,error,path,inputPath,outputPath,url,tabId,convert. Terminal states complete/failed/cancelled/interrupted; progress 0..1. Conversion pending/running. Download downloading/publishing.
Native host name com.tingjian.audio. Request {id,command,...}, response {id,ok,data,error}, event {event:'conversion',jobs:[{id,inputPath,outputPath,state,progress,error}]}. Commands hello, snapshot, chooseDirectory {purpose}, chooseFiles {folder,recursive}, convert {jobs:[{id,inputPath}],outputDirectory,bitrate}, cancel, publish {taskId,sourcePath,directory,filename}, cleanup {taskId,sourcePath}, open {path,reveal}. hello includes version, downloadDirectory, conversionDirectory, defaultDownloadDirectory; chooseDirectory returns {path}; chooseFiles returns {files:[{path,size}],errors:[]}; publish returns {path}. Empty publish directory uses OS Downloads. Host trusts only selected input paths and output dirs / its published files, validates staging path ending Tingjian/staging/<taskId>/<filename>. Host keeps local approvals and job state across connections, interrupted work is surfaced.
