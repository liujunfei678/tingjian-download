# 听见 2.0：常驻音频工作台设计

状态：用户已于 2026-10-18 确认并授权开发；实现及验证见项目计划与测试记录。

## 目标与已确认需求

保留现有网页音频捕获、名称提取、复制链接和批量下载能力，把听见升级为浏览器内的常驻音频工作台。

用户要求：

1. 资源分为已识别、未识别两组。
2. 点击插件后界面持续保留，点击关闭才关闭。
3. 界面更优雅、清楚、易操作。
4. 可以选择下载文件夹。
5. 把原有歌曲处理程序整合进插件。

第 5 项已确认指项目中现有的 **M4A 批量转 MP3 转换器**，不是歌词转文字、声音识别或网页录音。

本方案对“已识别”的定义是：有可用的音频专属名称或可读文件名。它不表示音乐指纹识别、曲库匹配或版权身份验证。

## 推荐方案与取舍

采用 **浏览器常驻侧栏 + Windows 本地转换组件**。

- 浏览器侧栏承担全部常用操作：发现资源、分组、下载、选择目录、添加转换文件、调整码率和查看进度。
- 本地组件复用 `converter/ConverterCore.cs` 和现有 FFmpeg，通过浏览器 Native Messaging 与插件通信。
- 首次需要配置一次本地组件，以后不必另开原桌面窗口；组件只在浏览器需要时启动。
- 没有配置组件时，资源识别、复制链接与浏览器默认目录下载仍可使用；自定义任意文件夹和本地转换显示明确的配置入口。

替代方案是把转换引擎重做为浏览器内 WebAssembly：可省去本地组件，但不能直接复用现有 C# 程序，转换速度和内存开销也有不同。当前推荐本地组件，优先保留原程序已验证的格式兼容性、取消、重试与文件保护行为。

## 界面与常驻行为

工具栏点击听见图标后打开当前浏览器窗口的侧栏。点击网页、播放音频、切换同一窗口的标签页都不自动关闭；用户点击关闭入口才关闭面板。浏览器或窗口本身关闭时，侧栏随之结束。

侧栏跟随所在浏览器窗口的活动网页，更新页面标题、域名和该页面的资源。每个标签页仍保有自己的资源缓存，切换页面不会把资源或选中项混到其他页面。

侧栏分为三个入口：

- **资源**：当前网页、识别数量、搜索、两个分组、选中与下载操作。
- **格式转换**：本地文件和下载后转换的队列、码率、输出目录、逐项与总进度。
- **设置**：保存目录、默认码率、本地组件状态、浏览器下载记录和安装帮助。

关闭侧栏不取消正在执行的下载或转换。后台负责执行，重新打开侧栏恢复任务状态。浏览器退出导致中断时，未完成任务标记为中断，可由用户重新开始，不把它们显示为成功。

### 视觉方向

保留“听见”的波形标识、米白背景和墨绿强调色。采用随侧栏尺寸变化的布局，取消现有固定的 440 × 600 尺寸。

顶部紧凑显示品牌、页面信息和导航；中间给资源和任务足够的可滚动空间；底部固定主要操作与保存目标。采用更清楚的字号层级、留白、细边框和一致的按钮状态，避免大量小字和重复的操作区。

## 两组资源

“资源”页显示两个可折叠分组，每组有独立数量：

| 分组 | 规则 | 示例 |
| --- | --- | --- |
| 已识别 | 最终采用的名称来自明确匹配的播放器/元素/链接，或可读的下载提示、服务器文件名、URL 文件名 | `远方 - 示例歌手.m4a` |
| 未识别 | 只能使用网页标题、随机编号或通用备用名 | `音乐合集.wav`、随机哈希文件名 |

默认展开“已识别”。未识别资源仍可下载、复制链接、加入支持的转换流程，不因分组而丢弃。

搜索作用于两组，保留各组匹配数量；支持按组全选、取消选择和批量操作。

命名算法统一输出 `filename`、`nameSource` 和 `nameRecognized`，合并资源时同步重算。网络响应确认字段 `verified` 继续只表示“确认为音频响应”，不得拿它判断歌曲名称是否已识别。

## 选择下载目录

提供两种保存方式：

1. **浏览器默认目录**：沿用现有下载 API 与浏览器设置，可保留每次另存为选项。
2. **自定义文件夹**：由本地组件打开系统目录选择器，选择磁盘上的文件夹，显示路径并在本机记住。批量下载使用同一个目标。

使用自定义目录时，网络下载仍先由浏览器发起，以保留现有 Cookie、签名 URL 和浏览器下载行为；完成后由本地组件把本次任务的文件发布到选择的文件夹。

暂存位置使用听见独占的下载子目录和任务标识。本地组件先复制到目标目录的临时文件，成功后发布正式文件；工作台保存最终路径和状态后，只清理听见自己创建的暂存文件及其暂存下载记录。自定义目录的最终文件由工作台任务记录打开或定位；普通浏览器下载方式继续使用浏览器下载记录。

不得覆盖已有同名文件；沿用自动编号。目录不可写、空间不足、组件中断或发布失败时显示失败原因，保留可重试的来源，不能提前显示成功。

## 格式转换功能

复用现有转换核心，支持：

- 多选 M4A 文件、选择文件夹、可选包含子目录。
- 128 / 192 / 256 / 320 kbps，默认 320 kbps。
- MP3 输出为 44.1 kHz、双声道，尽量保留现有文字标签。
- 选择输出目录，默认可跟随下载目录，也可单独选择。
- 逐个转换、进度、停止、失败详情和重试；已完成的文件保留。
- 中文名称、同名编号、损坏文件处理、原文件保留。

资源卡片对 M4A 增加“下载并转 MP3”。它先将原始 M4A 保存到下载目录，再把该文件加入转换队列，原始 M4A 保留。已有 MP3 直接下载，不再无意义地转码。

本次不扩展为歌词识别、网页录音、音乐指纹识别、DRM 处理或新的输入格式集合。现有独立桌面工具继续能运行。

## 组件边界与数据流

```mermaid
flowchart LR
  Page[网页与音频响应] --> Capture[现有捕获与命名]
  Capture --> Panel[常驻侧栏：资源与任务]
  Panel --> Browser[浏览器下载]
  Browser --> Temp[听见任务暂存文件]
  Temp --> Host[Windows 本地组件]
  Local[用户选择的本地 M4A] --> Host
  Host --> Core[现有转换核心与 FFmpeg]
  Host --> Output[用户选择的保存目录]
  Core --> Output
  Host --> Panel
```

- 捕获与名称处理留在当前扩展主干，保留签名参数、去重、拒绝非音频响应与跨标签页隔离。
- 后台分别管理资源缓存、浏览器下载、转换队列和本地连接；不把所有逻辑塞进现有捕获脚本。
- 本地组件复用 `FileScanner.Scan` 和 `BatchConverter.Run`，新增 Native Messaging 入口及队列控制，不把桌面窗体嵌入网页。
- 插件关闭面板后，后台与本地连接继续管理任务；重新打开面板读取当前状态。

## 本地组件配置与边界

提供 Windows 当前用户的一次性配置与取消配置工具，分别注册 Chrome / Edge 的本地主机。扩展使用稳定标识，主机只接受该扩展来源。

文件选择、目录选择和任务执行只由可信的听见界面触发；网页报告音频的消息不能直接调用本地文件操作。原始网页消息不能指定本地程序、命令或任意文件操作。

本地组件仅处理用户选择的输入、输出目录和听见本次下载产生的暂存文件；校验任务身份、文件路径、状态与参数。FFmpeg 继续按参数数组运行，不经过 shell。

音频处理在本机完成，不增加账号、上传接口、云端转码服务或开机常驻服务。不改动浏览器全局下载目录，不修改 PowerShell 执行策略。实际配置本地主机由用户运行交付包中的配置工具完成，本阶段不改动系统注册信息。

## 兼容与迁移

- 目标为 Windows 10 / 11 的桌面 Chrome / Edge，沿用当前插件与转换工具的平台范围。
- 对侧栏、关闭入口和本地通信做能力检测；不把常驻侧栏重新退化为失焦消失的 action popup。
- 保留现有保存偏好与下载方式；旧缓存缺少命名来源时统一补算，不能因缺字段把全部资源归入已识别。
- 本地组件未连接时给出设置入口，仍能进行默认目录的普通下载。
- 本次交付版本为 2.0.0。

## 验收标准

1. 同一页面中的明确歌曲名、服务器可读文件名与网页备用名进入正确分组，分组和搜索数量一致。
2. 真实侧栏点击网页后保持开启；切换标签页、导航、多窗口和关闭后重开时不串资源或任务状态。
3. 界面在侧栏的常见宽度、高度下没有裁切或被遮挡的主要操作，空状态、加载、禁用、失败和完成状态清楚。
4. 能通过系统对话框选择任意可写的普通文件夹，单个与批量文件实际出现在该目录，中文名称和重名保护正确。
5. 本地 M4A、AAC/ALAC 样本和网页下载 M4A 能转换为可解码的 MP3，码率、采样率与标签符合既有工具行为，原文件保留。
6. 转换停止、失败、重试、组件断开、目录不可写和下载取消不会产生被误标为成功的文件，也不清理其他文件。
7. 侧栏关闭后任务继续，重开后可见状态；浏览器退出或异常中断有明确结果。
8. 保留现有 16 项核心与 19 项浏览器测试，并增加分组、真实侧栏、目录选择、本地协议、实际 FFmpeg 和端到端任务测试。现有转换器测试继续通过。
