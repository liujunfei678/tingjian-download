# 2.0.1 筛选修复

状态：此筛选方案已按用户后续明确要求撤回。当前 2.0.2 的识别与命名恢复为 1.1，见 verification-2.0.2.md；本文仅保留历史排查记录。

用户反馈：旧版只有两条可下载音频，新版混入大量同名、下载报 SERVER_FORBIDDEN 的条目。此前只比较升级前 1.1 与 2.0，不能据此说最早版本没有扩大识别范围。

## 原版核对

直接读取 `dist/tingjian-audio-downloader-v1.0.0.zip`。其中 audio.js、content.js、background.js 的 SHA-256 与 `test-results/before-naming-update/extension` 对应文件完全一致。

1.0 中 candidate 无条件要求 isAudioURL；后续为了播放器元数据，给没有扩展名的 audio 元素增加了绕过条件。这允许没有音频 MIME、没有已知格式、也未收到成功响应的地址进入列表。使用原版与新版脚本在内存中执行同样输入已复现差异。命名变化和 URL 同名不足以解释可下载性，因此本次不按名称合并或更改签名参数。

## 修复边界

- 保持原版可识别的直接音频链接：有名字、随机/无名字都保留。
- 原版拒绝的无后缀播放器地址只暂存名称信息，最多 200 项，跟随标签页缓存清理；实际收到同一完整 URL 的音频响应后再显示并合并播放器名称。
- 旧缓存里的同类未确认项也会过滤。
- 浏览器下载无网页 tabId，原 webRequest 筛选不会关联到它的失败；现在仅把已登记下载明确报告的 SERVER_FORBIDDEN 回传到对应资源缓存。网络临时错误和用户取消保留重试，不据此删掉资源。
- 失败任务历史保留；不在后台重启时重复应用历史拒绝，避免删除后来恢复有效的资源。
- 用资源首次采集时间绑定下载任务。旧页面的延迟失败不会误删新页面同一地址；没有时间标记的旧任务不具有删除当前候选的权限。
